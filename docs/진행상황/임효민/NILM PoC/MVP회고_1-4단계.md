## 2. 잘된 것

- **인덕션 조리 세션 선병합(10분)이 최고 성적(F1 0.846, 일 단위 만점)을 만들었다.** EDA에서 "펄스형 주의"로 표시했던 가장 어려운 가전이 이벤트 재정의 하나로 1위가 됨. → 가전별 이벤트 정의가 모델 구조보다 큰 레버리지.
- **집계 계층을 올리면 오차가 흡수되는 경향은 재현됐다.** 다만 (정정) 96%는 채널-일 가중 수치이고 가구-일로는 93.3%, 무사용일 recall은 CI가 전 범위 — "수렴"이 아니라 "표본 부족으로 판단 불가"가 정확한 표현.
- **1단계 노트북의 스모크 테스트·자동 체크리스트가 작동했다.** 팀원 실행에서 오류 0건, 보고 블록 복사만으로 상태 공유 완료. 32채널·이벤트 수 검증이 자동이라 신뢰하고 다음 단계 진행 가능했다.
- **Val 세트 도입으로 임계값 선정 절차는 유효하게 만들었다.** 단, (정정) 96%는 채널-일 가중 수치이며 Test도 병합·네거티브 전략 등 후속 의사결정에 사용되어 **개발 결과로만 취급**한다 — 발표에 서비스 성능으로 인용하지 않는다.
- **예측 확률 저장 설계 덕에 3~4단계가 재추론 없이 2분 만에 끝났다.** 임계값·병합 파라미터 재실험도 즉시 가능.

## 3. 아쉬운 것 / 배운 것

- **소요 시간 추정 2.4배 오차 (3시간 → 7.5시간).** 학습만 계산하고 채널당 104만 윈도우 추론을 빠뜨림. 교훈: 파이프라인 시간 추정은 학습+추론+I/O 전 구간으로. (H200 서버에서는 추론이 초 단위라 다음 라운드부터 해소)
- **진행 로그를 파이프(tail)로 감싸 실시간 확인 불가였다.** 장기 실행 작업의 stdout은 파일 직접 기록으로.
- **이벤트 정밀도 미달의 주범은 짧은 가전.** 헤어드라이기(중앙 지속 1.5분)·다리미(18초 서모스탯 펄스)는 이벤트 파편화로 오탐이 실제의 2~3배. 인덕션에서 통한 처방(세션 병합)을 이 두 가전에도 적용해볼 것 — 임계값이 아니라 이벤트 정의의 문제로 보임.
- **가구 단위(93.3%)가 채널 단위(96.0%)보다 낮다.** OR 결합이라 한 채널의 거짓 활동이 가구 전체를 오염 — 5단계 알림 규칙에서 채널별 신뢰도 가중(EDA 적합도 점수)이 필요하다는 근거.
- **전자레인지가 의외의 약점(일 단위 48/56).** EDA 1순위 가전이지만 저사용 가구(H029 등)에서 놓침 발생 — 사용 빈도가 낮은 가구는 애초에 해당 가전을 안부 조합에서 빼는 가구별 온보딩 로직 필요.

## 5. 검수로 드러난 회고 자체의 오류 (09-02 추가)

- **용어 반전**: "거짓 안심"을 반대 방향으로 썼다. 서비스 용어(거짓 안심·거짓 경보)는 재실 정답이 있는 실험에서만 쓴다.
- **분모 선택**: 채널-일(224)은 가전 많은 가구를 과대 반영하고 표본이 상관됨. 서비스 단위는 가구-일(105)이며 신뢰구간은 가구 block bootstrap으로.
- **이벤트 매칭**: 30% 겹침 기준은 조각난 예측을 중복 계산 — 8채널에서 정답 예측 수가 감지 수를 초과하는 모순 발생. 1:1 매칭으로 교체.
- **Test 오염**: 병합·네거티브 전략을 Test를 보고 결정했으므로 Test는 이미 개발 세트. 16가구 전체가 EDA에 쓰여 holdout도 불가.
- **성공 기준의 성급함**: "95% 통과"를 표본 16건짜리 지표로 선언했다. 사전 기준은 있었지만 표본 크기 조건이 없었다.
