## 모델 입력 계약

TCN 모델 입력은 PyTorch `Conv1d`에서 일반적으로 사용하는 `(N, C, L)` 구조를
기준으로 다음과 같이 정의했다.

```text
dtype: float32
shape: (batch_size, feature_count, sequence_length)
단건 추론 shape: (1, 4, 299)
샘플링 주기: 1Hz
시간 순서: 과거 → 현재
```

입력 Feature 순서는 다음과 같이 고정한다.

| Feature Index | 필드 | 한글명 | 단위 |
| ---: | --- | --- | --- |
| 0 | `active_power` | 유효전력 | W |
| 1 | `reactive_power` | 무효전력 | var |
| 2 | `power_factor` | 역률 | 단위 없음 |
| 3 | `current` | 전류 | A |

시간축 Index 0에는 가장 오래된 측정값, Index 298에는 가장 최근 측정값을 넣는다.

실제 전달받을 checkpoint가 `(N, 4, 299)`를 입력받는지는 AI 담당자에게 최종
확인해야 한다. 학습 모델이 `(N, 299, 4)`를 사용했다면 모델 호출 전에 축을 변환해야 한다.

## 입력 정규화

센서와 MQTT-Kafka Bridge는 정규화하지 않은 원래 물리 단위의 측정값을 전송한다.
`realtime-analysis-service`가 모델을 호출하기 직전에 manifest에 기록된 학습 데이터의
평균과 표준편차를 적용한다.

```text
normalized_value = (raw_value - mean) / std
```

실시간 데이터에서 평균과 표준편차를 다시 계산하지 않는다. 학습과 추론에 반드시 같은
고정값을 사용한다.

manifest의 `input`은 전달되는 원시 입력의 구조를 설명하고, `preprocessing`은 그 입력에
적용할 변환을 설명한다. JSON 필드 순서는 동작에 영향을 주지 않지만 처리 흐름을 쉽게
읽을 수 있도록 `input → preprocessing → output` 순서로 작성한다.

## 모델 출력 계약

모델은 다음 형식으로 가전 6종의 ON 확률을 반환한다.

```text
dtype: float32
shape: (batch_size, 6)
단건 추론 shape: (1, 6)
값의 범위: 0.0 ~ 1.0
```

여러 가전이 동시에 ON일 수 있는 멀티라벨 문제이므로 각 출력에 독립적으로
`sigmoid`를 적용한다. 하나의 클래스만 선택하고 전체 확률의 합을 1로 만드는
`softmax`는 사용하지 않는다.

모델의 공식 출력은 반올림하거나 Boolean으로 변환하지 않은 확률이다. 최종 ON/OFF는
실시간 분석 서비스가 manifest의 가전별 threshold를 적용해 판단한다.

```text
ON  = probability >= threshold
OFF = probability < threshold
```

확률과 판정을 분리하면 모델을 다시 배포하지 않고 threshold를 조정할 수 있고, 확률
이력을 이용해 오탐과 미탐을 분석할 수 있다. 이후 연속 판정, 히스테리시스, 세션 병합과
같은 시간 규칙도 분석 서비스에서 함께 적용할 수 있다.

    }
  },
  "output": {
    "dtype": "float32",
    "shape": [-1, 6],

## 추가 구현 — 확률 기반 Predictor와 판정 구조

AI 모델 학습이 완료되기 전에도 후속 개발을 진행할 수 있도록 모델 의존 영역과 상태
판정 영역을 분리했다.

```text
HouseholdBuffer
  → Predictor: 가전 6종 ON 확률 반환
  → ApplianceStateDecider: Manifest threshold 적용
  → ApplianceState: 확률, threshold, ON/OFF 결과
  → DailyActivityTracker
```

- `AppliancePrediction`에 가전 코드와 `0~1` 확률을 저장한다.
- `FakePredictor`는 ON 설정 가전에 `1.0`, 나머지 가전에 `0.0`을 반환한다.
- `ModelManifest`가 입력 shape, Feature 순서, 전처리 방식, 출력 순서와 threshold를 검증한다.
- `ApplianceStateDecider`가 가전별 확률과 threshold를 비교해 최종 ON/OFF를 만든다.
- Predictor가 가전을 누락하거나 중복·알 수 없는 가전을 반환하면 처리를 실패시킨다.
- 실제 모델 연동 전까지 `config/model_manifest.json`의 threshold `0.5`를 임시로 사용한다.

## 추가 구현 — 가전 ON/OFF 상태 변화 감지

TCN이 반환하는 6개 가전별 ON 확률의 순간적인 흔들림을 그대로 상태 변화로 확정하지
않도록 연속 판정과 히스테리시스를 적용하는 감지기를 추가했다.

```text
PowerMeasurement 299초 버퍼
  → Predictor: 6개 가전별 ON 확률
  → 가전별 threshold 1차 판정
  → ApplianceStateTransitionDetector: 연속 판정 및 히스테리시스 적용
  → TURNED_ON / TURNED_OFF
```

- ON과 OFF 모두 기본 3개 연속 샘플이 확인돼야 상태를 변경한다.
- ON 상태에서는 `threshold - 0.05` 이하가 될 때까지 기존 상태를 유지한다.
- 중복되거나 과거 시각의 상태 입력은 다시 전이시키지 않는다.
- `TURNED_ON`이 확정된 가전만 당일 사용 가전으로 기록한다.
- 변화 시작 시각과 확정 시각을 각각 `occurred_at`, `confirmed_at`으로 보존한다.
- 연속 샘플 수와 히스테리시스 폭은 환경변수로 변경할 수 있다.
- 별도의 유효전력 변화점 감지는 사용하지 않는다.

### 검증 결과

- 전체 단위 테스트 통과
- 연속 ON/OFF, 확률 반동, 히스테리시스 검증
- Handler에서 확정된 `TURNED_ON`만 일일 활동으로 기록하는 흐름 검증

현재 단계에서는 상태 전이를 로그 및 메모리에서 확인한다. 다음 작업에서 이 전이를
`appliance_usage_session`의 시작·종료 및 최대 확률 갱신에 연결한다.
