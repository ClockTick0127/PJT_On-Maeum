- DB 초기화 스크립트(`01-create-databases.sql`) 추가 — 새 환경에서 `docker compose up`만 하면

- 인프라 전체를 `infrastructure/` 폴더로 재구성 (postgres, keycloak, kafka, mqtt, 브릿지)
- mqtt 브로커·시뮬레이터를 infrastructure로 이전 (팀원 협의)

### 3. Spring Boot 백엔드 3종 세트

- api-gateway(8080) / iot-device-service(8081) / monitoring-service(8082) 독립 Gradle 프로젝트 구성
- 버전: Java 21 / Spring Boot 3.5.16 / Spring Cloud 2025.0.3 / Gradle 8.14.3
- gateway: 환경변수 기반 라우팅(`/api/devices/**`, `/api/monitoring/**`), CORS, WebFlux(Netty)
- 도메인 서비스: JPA + Flyway(ddl-auto 금지), 공통 오류 응답 + 전역 예외 처리, Validation,
  OpenAPI(Swagger), Actuator, H2 기반 테스트 환경
- 설정은 `application.properties` 하나 + `src/test/resources` 테스트 오버라이드 방식
- 모든 값은 `${환경변수:기본값}` 패턴 — 기본값은 로컬(localhost), 배포 시 환경변수로 덮어씀
- 서비스별 멀티스테이지 Dockerfile(JDK 빌드 / JRE 실행) + `backend/compose.yaml`로 컨테이너 실행
- 빌드·실행·라우팅·DB 연결·검증 오류 응답까지 완료 조건 전부 확인

### 4. Keycloak 인증·인가

- keycloak 컨테이너(26.4, keycloak_db 사용) 추가, 포트 8090
- realm `nilm`, 역할 ADMIN / GUARDIAN / USER, React용 public client(react-dashboard), 테스트 사용자 생성
- 도메인 서비스: JWT 검증 + `realm_access.roles` → `ROLE_*` 변환 컨버터, 역할 기반 인가(`hasRole`)
- gateway: 1차 JWT 검증(유효성만), 역할 인가는 각 서비스 담당 — 2중 검증 구조
- `app.security.enabled` 스위치로 Keycloak 없이도 로컬 실행 가능 유지
- Docker 환경 issuer 불일치 문제 해결: 검증 기준(issuer-uri)과 공개키 조회(jwk-set-uri) 주소 분리
- Postman으로 401(무토큰) / 200(유효 토큰) / 403(권한 부족) 시나리오 전부 검증

### 5. Kafka 파이프라인

- Kafka(KRaft 단일 노드, 3.9.0) + Kafka UI(8091) 추가 — ZooKeeper 없이 컨테이너 하나
- 토픽 `power.raw.v1` 생성 (파티션 3)
- MQTT–Kafka 브릿지(`infrastructure/mqtt-kafka-bridge`, Python) 구현:
  `v1/power/sim/+/main` 구독 → 필수 필드 검증 → **가구 ID를 key로** `power.raw.v1` 발행
- key=house 덕분에 가구별 파티션 고정 → 순서 보장 + 분석 서비스 수평 확장 기반 마련
- 시뮬레이터(10가구, 1초 주기) → MQTT → 브릿지 → Kafka 엔드투엔드 확인

## 트러블슈팅에서 배운 것

- **Spring Cloud 버전**: 존재하지 않는 BOM 버전을 쓰면 의존성 전체가 버전 없이(`:.`) 깨진다.
  버전은 Maven Central에서 실존 여부를 확인하고 쓸 것.
- **CRLF 지옥**: Windows Git의 자동 줄바꿈 변환이 `gradlew`를 CRLF로 만들면 Linux 컨테이너에서
  exit 127로 죽는다. `.gitattributes`(근본) + Dockerfile의 `sed`(방어선) 이중 대응.
- **properties vs compose 문법**: Spring은 `${VAR:기본값}`, compose는 `${VAR:-기본값}`.
  compose용 줄을 properties에 붙여넣으면 순환 참조로 앱이 죽는다. 파일마다 자기 문법만.
- **compose 반영 규칙**: `restart`는 설정 변경을 반영하지 않는다. 환경변수는 `up -d`(재생성),
  properties는 jar에 구워지므로 `--build` 필요.
- **`.env`는 Docker Compose 전용**: bootRun은 .env를 모른다. `spring.config.import`로 읽게
  하거나 환경변수/IntelliJ 실행 설정으로 주입.
- **git rm --cached는 add 취소가 아니다**: add 취소는 `git reset`. 파일은 안 지워지지만
  인덱스가 꼬여서 놀라게 된다.
- **Keycloak 계정**: 이름·이메일이 비면 direct grant가 "Account is not fully set up"으로 거절된다.
- **git checkout 폴더 삭제 실패**: 터미널이 그 폴더에 들어가 있으면 Windows가 삭제를 막는다.
