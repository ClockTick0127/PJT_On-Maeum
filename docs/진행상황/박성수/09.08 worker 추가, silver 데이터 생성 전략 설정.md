## Bronze → Silver 데이터 변환 전략

대용량 원본 데이터를 한 번에 전체 압축 해제할 경우 약 5~6TB의 저장공간이 필요할 것으로 예상된다.

현재 장비의 저장공간으로 원본 전체를 동시에 보관하는 것은 어렵기 때문에,  
원본 압축파일을 일부씩 처리하는 **Streaming 형태의 단계적 전처리 방식**을 사용하기로 결정했다.

### 처리 흐름

```text
대용량 압축파일
        │
        ▼
일부 파일 압축 해제
        │
        ▼
CSV → HDFS 업로드
        │
        ▼
Spark 분산 전처리
        │
        ├── CSV Parsing
        ├── "?" → NULL 변환
        ├── Schema Validation
        ├── Timestamp 변환
        ├── Float32 타입 변환
        ├── Repartition
        └── ZSTD Parquet 압축
        │
        ▼
Silver Parquet → HDFS 저장
        │
        ▼
처리 완료된 CSV 삭제
        │
        ▼
다음 압축 데이터 처리
```

### 상세 처리 단계

1. 메인 PC에서 대용량 압축파일의 일부만 압축 해제한다.
2. 압축 해제된 CSV 파일을 HDFS에 업로드한다.
3. Spark를 이용해 다음 전처리를 수행한다.
   - CSV 파싱
   - `"?"` 값을 `NULL`로 변환
   - 데이터 스키마 검증
   - Timestamp 컬럼 변환
   - 실수형 데이터를 `float32` 기반 타입으로 변환
   - 데이터 분산 처리를 위한 Repartition
   - ZSTD 기반 Parquet 압축
4. 생성된 Silver 데이터를 HDFS에 저장한다.
5. Silver 변환이 완료된 원본 CSV 파일을 HDFS에서 제거한다.
6. 위 과정을 반복하여 전체 압축파일을 순차적으로 처리한다.
7. 최종적으로 해당 과정을 자동화한다.

## 데이터 계층 정의

현재 전처리 단계에서는 다음과 같이 데이터 계층을 구분한다.

### Bronze

원본 데이터에 최대한 가까운 상태

- 원본 CSV
- `"?"` 등 원본 표현 유지
- AI 학습용 타입 최적화 이전 상태

### Silver

데이터 전처리 이전 용량 감소와 기본 검증을 수행한 상태

- Parquet 포맷
- ZSTD 압축
- 명시적 스키마 적용
- Timestamp 타입 정규화
- Float 타입 최적화
- `"?"` → `NULL`
- 스키마 검증 완료
- Spark 연산에 적절한 단위로 Partition 구성

## 이번 결정의 목적

이번 전처리 구조의 핵심 목적은 다음과 같다.

- 5~6TB 규모의 원본 데이터를 전체 압축 해제하지 않고 처리
- 제한된 로컬 저장공간을 효율적으로 활용
- HDFS를 이용한 분산 저장 구조 실습
- Spark를 이용한 대용량 분산 전처리 구조 구현
- CSV 대비 저장 용량 및 읽기 효율 개선
- AI 학습 단계에서 반복되는 데이터 타입 변환 및 정제 작업 최소화
- 추후 새로운 데이터가 추가될 경우 Schema Validation을 통해 데이터 이상을 조기에 확인

## 확인이 필요한 사항

- `worker-jm` 병목 원인 분석
- 노드별 네트워크 속도가 Spark 처리 성능에 미치는 영향 측정
- HDFS Block Size 및 Replication Factor 최적값 검토
- Spark Partition 개수 및 파일 크기 최적화
- 30Hz 데이터를 10Hz 또는 1Hz로 다운샘플링할지 여부
- 다운샘플링 시 NILM 모델 성능에 미치는 영향 확인
- Parquet 파일의 적절한 목표 크기 결정
- 전체 Bronze → Silver 파이프라인 자동화 방식 설계
