### 1. 로컬 SonarQube 환경 구축 및 분석

팀에서 이미 `sonar-project.properties`와 `infrastructure/local/compose.sonar.yaml`을
준비해둔 상태라, iot-device-service는 소스·테스트·JaCoCo·라이브러리 경로에 이미 포함돼 있었다.

**공용 서버 대신 로컬 SonarQube를 쓴 이유**: Community Edition은 브랜치 분석을 지원하지 않아
프로젝트 키가 하나뿐이다. feature 브랜치에서 공용 서버로 스캔하면 **팀 대시보드가 내 브랜치
결과로 덮인다**(파괴적이진 않고 develop 재스캔으로 복구되지만, 그 사이 팀이 잘못된 숫자를 본다).
그래서 개발 중 점검은 로컬, 공식 기록은 develop 병합 후 공용 서버로 나누기로 했다.

분석 절차 (2단계):
```
① gradlew test jacocoTestReport copySonarLibraries copySonarTestLibraries
② docker run --rm --network nilm-sonarqube_default -e SONAR_HOST_URL=http://sonarqube:9000 \
     -e SONAR_TOKEN=... -v "%cd%:/usr/src" -w /usr/src sonarsource/sonar-scanner-cli
```

### 3. 인증·초대 도메인 단위 테스트 38건 추가 — 커버리지 19% → 46%

E2E로 눈으로 확인한 것과 별개로, **자동 재검증되는 테스트가 없으면 커버리지는 0**이다.
품질 게이트가 "새 코드 80%"를 요구하므로 신규 인증 코드에 테스트가 필요했다.

"틀리면 실제로 아픈 로직"만 골라 작성했다(DTO·getter는 제외):

| 테스트 | 검증 |
| --- | --- |
| HouseholdInviteTest (5) | 만료·사용됨·회수됨 각각 거부, 회수가 다른 사유보다 우선 |
| HouseholdMemberTest (4) | 부분 수정 시 null 필드 유지, 기본값, 복합키 동등성 |
| UserProfileTest (4) | 기관 소속 → PENDING, 공백 입력으로 승인 절차 우회 불가 |
| InviteServiceTest (9) | 코드 형식(혼동 문자 제외 8자리), 기본 72시간, 비멤버 발급 차단, 만료 시 멤버십 미생성 |
| MembershipServiceTest (7) | 비멤버 403, 없는 가구 404, 중복 방지, 마지막 멤버 해제 차단 |

결과: 38건 전부 통과(스프링 미기동, 수 초 소요).
`InviteService` 12%→88%, `HouseholdMember` 0%→94%, `HouseholdInvite` 0%→87%,
`MembershipService` 9%→74%.

**E2E로는 확인할 수 없었던 두 가지를 이번에 검증했다**: 72시간 만료 판정, 마지막 멤버 해제 차단.

## 배운 점

- 커버리지는 품질의 보증이 아니라 **"검증 안 된 분기"를 찾는 지도**다. 숫자를 목표로 삼으면
  getter 테스트로도 올릴 수 있어 무의미해진다. "이 분기가 틀리면 사용자가 뭘 겪나"로 고르는 게 맞다
- 도메인 엔티티에 규칙을 넣어두면(초대 만료 판정, 상태 전이) 스프링 없이 테스트할 수 있어
  검증 비용이 크게 낮아진다

## 이슈 / 팀 공유

- **SonarQube 컨테이너 기동 실패**: Elasticsearch가 자기 호스트명을 해석하지 못해 재시작 루프.
  `hostname` + `extra_hosts` 오버라이드로 해결했으나 현재는 로컬 임시 파일로만 적용.
  팀원들도 같은 증상을 겪을 것이므로 `compose.sonar.yaml` 반영 여부를 작성자와 상의 필요
- CSRF 지적 2건은 Won't Fix 처리 예정 — 쿠키 기반 인증으로 전환하면 반드시 재검토
