## 오늘 한 일

### 1. 파트 배정 및 도메인 설계 정리 (파트 1+2: Gateway + IoT Device Service)

- 백엔드 도메인 분담 확정: **1+2(Gateway·기기) / 3(실시간 분석) / 4(모니터링)** 중 1+2 담당
- 담당 범위의 핵심 기술 이슈 정리
  - Gateway: SSE 프록시 통과(버퍼링·read timeout이 스트림을 끊는 문제 → 라우트별 타임아웃 해제 + heartbeat), JWKS 캐싱(Keycloak 장애 시에도 토큰 검증 유지), **기기 토큰 vs 사용자 토큰 분리**(client credentials vs authorization code, 경로별 접근 매트릭스)
  - IoT Device Service: 기기 생명주기(REGISTERED→ACTIVE→SUSPENDED→RETIRED), Mosquitto 인증/ACL 연동(MVP는 passwd 파일 방식, 확장 시 플러그인)
- 지라 백로그 항목 정리 (조사 4건 · Gateway 4건 · Device Service 5건 · 계약/문서 2건)

### 2. device_db ERD 설계 및 ERDCloud 반영

- **DB 경계 확정**: 유저_DB는 Keycloak 제공(개발자 무접촉), 디바이스_DB는 가구·센서장치·설치 이력·기기 인증 담당
  - 연결 고리는 `keycloak_user_id`(UUID) 값 참조뿐 — FK 없음
  - 보호자↔가구 매핑·알림 연락처는 Keycloak이 아닌 device_db 소유로 결정 ("Keycloak은 누구인지만, 우리 DB는 서비스에서의 관계를")
- **테이블 7개 설계**: households / household_guardians / devices / install_history / device_credentials / device_certificates / device_acl
- 설계 원칙 6개 문서화: Keycloak 무접촉, 서비스 간 FK 금지(house_id 값 공유), 상태·이력 분리, 삭제 대신 상태 전이, 자격증명 해시만 저장(DB가 원본·passwd 파일은 파생물), UTC timestamptz 통일
- 화면 6종(보호자 홈·실시간 대시보드·안부 캘린더·알림 상세·기기 관리·설정)에서 필요한 값을 역산해 컬럼 근거 확보
- **ERDCloud 반영 완료**: DDL Import로 팀 다이어그램("1차 ERD")에 테이블 7개 + 관계 6개 생성, Export SQL로 무손실 확인

## 배운 점

- ERD의 관계선은 결국 "FK가 어디 있느냐"의 시각화 — 1:N은 N쪽에 FK, N:M은 다리 테이블로 분해
- 외부 시스템(Keycloak) 참조는 FK를 걸 수 없으므로 값 참조 + 컬럼 코멘트로 의도를 남겨야 다이어그램만 보는 사람이 헷갈리지 않음
- 컬럼은 감이 아니라 화면에서 역산 — 화면에 안 나오는 컬럼은 존재 이유를 의심
