### 2. device_db 스키마 및 기기 생명주기 API 구현 (`feature/back/device-domain`, 24파일 1,017줄)

- **V2 마이그레이션**: ERD 6테이블 + check 제약 + 인덱스 (Flyway)
- **도메인**: 상태 전이 규칙을 Device 엔티티에 내장 — 허용 맵(REGISTERED→ACTIVE, ACTIVE↔SUSPENDED, any→RETIRED) 밖의 전이는 예외
- **서비스**: 기기 등록 = 저장 + MQTT 계정 발급 + ACL 생성 + 설치 이력 기록을 한 트랜잭션으로. RETIRED 전이 시 계정 자동 폐기
- **API**: 가구 등록/조회, 기기 등록/조회/상태전이/이력 (Swagger 문서화)
- 팀 공통 GlobalExceptionHandler 무접촉 — 별도 DomainExceptionHandler(404/400/409) 추가
- 단위 테스트: 상태 전이 4케이스 (정상 생명주기 / 불법 전이 거부 / RETIRED 종착 / 자기 전이 거부)

### 3. 실제 PostgreSQL 위에서 실행 검증 (DoD 실측)

| 시나리오 | 기대 | 실측 |
| --- | --- | --- |
| 가구 등록 | 201 | ✅ |
| 기기 등록 (계정·ACL 발급) | 201 + mqtt 계정/비밀번호 1회 노출 + ACL `v1/power/sim/{house}/#` | ✅ |
| REGISTERED→ACTIVE | 200 | ✅ |
| 불법 전이 ACTIVE→REGISTERED | 400 INVALID_STATE_TRANSITION | ✅ |
| ACTIVE→RETIRED | 200 + 계정 폐기 | ✅ (DB에서 revoked_at 확인) |
| 이력 조회 | INSTALLED→STATUS_CHANGED→RETIRED 3건 | ✅ |
| 중복 가구 등록 | 409 DUPLICATE_RESOURCE | ✅ |

- DB 확인: secret_hash가 BCrypt(`$2a$...`)로 저장 — "자격증명 해시만" 원칙 준수 확인

## 트러블슈팅

- **H2 테스트 실패**: `TIMESTAMPTZ` 축약형을 H2가 미지원 → 표준 표기 `TIMESTAMP WITH TIME ZONE`으로 변경 (PG/H2 양쪽 호환)
- **DB 접속 실패**: postgres 볼륨이 과거 비밀번호로 초기화돼 있어 `.env` 값과 불일치 — `POSTGRES_PASSWORD`는 볼륨 최초 생성 시에만 적용됨. 로컬 기동 시 실제 볼륨의 비밀번호 사용 필요
- **8081 포트 충돌**: 로컬에 다른 프로세스가 8081 점유 시 `SERVER_PORT` 환경변수로 우회 기동 (예: 8083)

## 배운 점

- 상태 전이 규칙은 서비스가 아니라 도메인 엔티티가 소유하게 하면, 규칙 위반이 코드 어디서든 원천 차단되고 단위 테스트도 스프링 없이 가능
- 비밀번호류는 "평문은 발급 응답 1회 노출, 저장은 해시"가 표준 패턴 — Mosquitto passwd 파일은 DB에서 파생시키는 방향으로
