# 진행 상황 회고 (0907, 채지현)

## 오늘 한 일 — MVP 1안 정의 (기능 최소형)

MVP 정의: **"총 전력 하나만 보고 → 가전 ON/OFF를 맞히고 → 루틴 이탈을 표시한다"**

### 만드는 것 (In)

| # | 구성 요소 | 스펙 |
| --- | --- | --- |
| 1 | 센서 노드 1대 | SCT-013 + ESP32, 멀티탭 1개, 초당 10회 전송 |
| 2 | 가전 3종 | 전기포트, 전자레인지, 선풍기 (쉬움 2 + 중간 1) |
| 3 | 감지 로직 | 이동평균 + 임계값 변화점 감지 → 시그니처 3장과 매칭. 파이썬 단일 프로세스 |
| 4 | 정답지 | 스마트플러그 3개 → 온오프 로그 자동 수집 |
| 5 | 화면 1장 | 현재 전력 그래프 + "☕ 포트 ON" 카드 + 오늘의 루틴 체크(아침 포트 ✅/❌) |
| 6 | 알림 1개 | "평소 시각까지 포트 미사용" → 문자/카톡 1건 발송 |

### 안 만드는 것 (Out — MVP 이후로 미룸)

- ❌ Kafka, Spark, Redis, HDFS (분산 스택 전부) → 파이썬 스크립트 + SQLite로 대체
- ❌ 딥러닝 (Seq2Point/UNet) → 규칙 기반 매칭만
- ❌ AI-Hub 110가구 학습 → 우리 집 실측 며칠이면 시그니처 3장 확보 가능
- ❌ 가전 5종, 다가구, 본인 확인 에스컬레이션, 여행 모드

### 시그니처 수집 계획 (AI-Hub 없이 가능한 근거)

규칙 기반 시그니처는 딥러닝 학습이 아니라 **통계량 추정** — 가전당 온오프 사이클 20~30회면 충분.

| 피처 | 예: 전기포트 | 안정 추정에 필요한 사이클 |
| --- | --- | --- |
| ΔPower (켜질 때 점프량) | +1,750~1,850W | ~10회 |
| 정상상태 소비 범위 | 1,780~1,830W | ~10회 |
| 지속 시간 분포 | 2~5분 | ~20회 |
| 기동 모양 | 즉시 계단 (surge 없음) | ~5회 |

- **모드 A — 의도 수집 (반나절)**: 가전 3종 × 20회 반복 온오프, 조건 섞어서(물 양·출력·풍속) 2~4시간에 60회 완료
- **모드 B — 자연 사용 검증 (3~5일)**: 배경 가전 겹침·전압 변동 등 현실 노이즈 속 시그니처 유효성 확인 + 루틴 통계 초기 샘플 축적
- 데이터 용량: 초당 10샘플 × 7일 ≈ 350MB — SQLite로 충분, 용량은 애초에 제약 아님
- MVP는 우리 집 한 곳 전용이므로 가전당 20~30사이클이면 충분. 110가구 데이터는 "처음 보는 집에서도 되는가"(RQ2, 딥러닝 일반화) 단계부터 필요 — "AI-Hub를 MVP에서 뺀다"의 정확한 근거

### 구조

```
멀티탭(가전3) → 클램프+ESP32 → WiFi → FastAPI 서버(파이썬)
                                        ├─ 감지: 이동평균+매칭
                                        ├─ SQLite: 이벤트 기록, 루틴 통계
                                        └─ 웹 화면 + 알림 발송
```

### 완성 판정 기준 (DoD)

1. 포트를 켜면 **5초 안에** 화면에 "포트 ON" 표시
2. 30회 온오프 테스트에서 스마트플러그 정답 대비 **정확도 80% 이상**
3. "아침 9시까지 포트 미사용" 시나리오에서 알림 문자 실제 발송

### 일정 (2주)

- 1주차: 센서 조립+캘리브레이션(2일) / 감지 스크립트+채점(2일) / 시그니처 3장(1일)
- 2주차: FastAPI+화면(2일) / 루틴 통계+알림(2일) / 통합 테스트+측정(1일)

### 설계 근거

- **분산 스택 제외**: MVP의 리스크는 "감지가 되냐"이지 "Spark가 도냐"가 아님. 감지가 증명되면 Spark 이식은 공정, 안 되면 지을 이유가 없음
- **가전 3종**: 유형 대표(저항가열/저항가열+짧음/모터) 커버 + 시그니처 작성 부담 최소
- **SQLite**: 하루 수십 이벤트 규모 — DB 선택 논쟁 자체가 낭비
- 핵심 원칙: **핵심 검증과 아키텍처 확장의 분리**

### Q&A

**Q. 루틴 이탈 표시는 패턴 분석 AI가 필요한 것 아닌가?**
A. MVP에서는 통계(사용 시각 분포 평균±표준편차 + 유예시간)로 충분하고, 데이터가 2주뿐인 초기엔 통계가 더 적합. 알림 문구가 곧 설명이 되는 장점도 있음(설명 가능성).
