## 2. 실기기(MCU) 전환 시 우리 구조 점검

시뮬레이터를 물리 기기로 바꾼다면 어디에 무엇이 필요한지 따져봤다.

### MCU의 역할 — 원천 데이터 공급만, 분석은 전혀 안 함

이 시스템에서 기기가 할 일은 "분전반 전력이 매 초 몇 W였는가"를 보내는 것 하나다.
가전 식별도 위험 판단도 전부 서버 쪽이다. 기기에 분석을 넣지 않는 이유:

- 가전 식별 모델은 계속 바뀐다. 펌웨어에 넣으면 정확도 개선마다 전 기기 업데이트가 필요하다
- 기기가 "냉장고 켜짐"으로 요약해 보내면 **원본 파형이 사라져 재학습이 불가능**하다.
  Bronze 레이어의 존재 이유가 이것이다
- 분산 처리(Spark)를 MVP에 넣기로 했으므로 원천이 서버에 쌓여 있어야 한다

다행히 MCU가 들어올 자리는 이미 계약으로 파여 있다. 시뮬레이터를 만들 때 정한
토픽(`v1/power/sim/{houseId}/main`) · 페이로드(`{house, device, ts, power_w}`) · QoS 1이
그대로 펌웨어 요구사항이 되고, 브릿지·Kafka·적재기는 손댈 필요가 없다.

### 선결 과제 (가) — 브로커 설정에 `acl_file`이 없다

`MqttPasswdSyncService`(mqtt-credential-lifecycle 브랜치)가 `device_acl`을 읽어
`acl.device` 파일을 생성하지만, `mosquitto.conf` / `.local.conf` / `.production.conf`
어디에도 `acl_file` 지시자가 없다. **현재는 인증만 걸려 있고 인가는 걸려 있지 않다** —
계정 하나가 유출되면 다른 가구 토픽에도 발행할 수 있다.

다만 이건 방치가 아니라 순서 문제다. `acl_file`을 켜는 순간 파일에 없는 계정이 전부
차단되는데, 시뮬레이터·브릿지 계정은 `device_db`에 없으므로 같이 끊긴다. 동기화 코드에도
이 조건을 주석으로 적어뒀다.

활성화하려면 시뮬레이터·브릿지 계정을 어떻게 처리할지 먼저 정해야 한다 —
`device_db`에 등록할지, 정적 ACL 항목으로 파일에 병기할지. 실기기가 붙기 전에는
반드시 닫아야 하는 항목이다.

### 선결 과제 (나) — 토픽에 구현 주체 이름(`sim`)이 박혀 있다

`v1/power/sim/{houseId}/main`의 `sim`은 시뮬레이터라는 뜻인데, 실기기가 이 토픽으로
쏘면 이름과 실제가 어긋난다. 바꾸려면 세 곳을 동시에 옮겨야 한다:
`DeviceService.TOPIC_PATTERN`, 브릿지 구독 패턴(`MQTT_TOPIC`), 기존 `device_acl` 행.
팀 계약 변경이라 합의가 필요하다.

### 선결 과제 (다) — LWT(Last Will and Testament)가 설계에 없다

안부 확인 시스템에서 **데이터가 안 오는 것 자체가 신호**인데, 그게 정전인지 Wi-Fi
끊김인지 기기 고장인지 구분하지 못하면 네트워크가 끊길 때마다 보호자에게 위험 알림이
가는 오경보 시스템이 된다. MQTT의 LWT를 쓰면 기기가 끊겼을 때 브로커가 대신
오프라인 메시지를 발행해 주므로 이 구분이 가능해진다. 현재 설계에 없어 추가가 필요하다.

같은 이유로 펌웨어 쪽에는 오프라인 버퍼링(재접속 시 백필)과 SNTP 시각 동기화가
필요하다. 전자는 우리가 at-least-once라 중복 부담 없이 넣을 수 있고, 후자가 없으면
네트워크 지연이 타임스탬프에 섞여 이벤트 정렬이 흔들린다.

## 배운 점

- **계약을 먼저 고정해두면 구현 주체가 바뀌어도 하위 시스템이 흔들리지 않는다.**
  시뮬레이터를 만들 때 정한 토픽·페이로드·QoS가 그대로 MCU 요구사항이 됐고,
  기기 자격·ACL·상태 전이도 물리 기기를 전제로 설계해둔 덕에 재작업이 없다
- 다만 **계약에 구현 주체 이름(`sim`)을 넣은 건 실수였다.** 계약은 "무엇을 보내는가"만
  담아야 하고 "누가 보내는가"는 빠져야 했다. 지금 바꾸려니 세 곳을 동시에 건드려야 한다
- 보안 기능은 "만들어 뒀다"와 "켜져 있다"가 다르다. ACL은 파일까지 생성되고 있었지만
  브로커가 읽지 않으니 실제 효력은 0이었다. 만든 것과 적용된 것을 따로 확인해야 한다
