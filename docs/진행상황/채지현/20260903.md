# 진행 상황 회고 (0903, 채지현)

## 오늘 한 일

### 1. HDFS 데이터 레이크 구축 (`feature/infra/hdfs`)

- NameNode + DataNode를 **별도 compose**(`infrastructure/hdfs/docker-compose.yml`)로 추가
  - 메인 docker-compose.yml은 수정하지 않음 — backend와 동일한 `nilm-net` 외부 합류 패턴
  - 복제 계수 1(로컬 DataNode 1대 최적화), named volume으로 데이터 보존
- 데이터 레이크 디렉토리 구조 생성
  ```
  /data/raw/         공개 데이터셋 원본 (AI-Hub, ENERTALK)
  /data/stream/      Kafka에서 적재되는 측정 스트림
  /data/processed/   Spark 전처리 산출물
  /data/events/      감지된 온오프 이벤트
  ```
- 검증: put/get 왕복 성공, Live datanodes 1, NameNode UI(:9870) 정상

### 2. Kafka → HDFS Parquet 적재 잡 구현 (MVP DoD)

- `infrastructure/hdfs/loader/` — 도커 컨테이너로 nilm-net 안에서 동작 (WebHDFS 사용)
- 동작: `power-raw` 구독 → 60초 버퍼링 → `house=/date=` 파티션 Parquet(snappy) 적재
- 설계 포인트
  - **스몰 파일 방지**: 메시지 단위가 아닌 60초 배치 플러시
  - **유실 방지(at-least-once)**: 플러시 성공 후에만 오프셋 커밋, 종료 신호 시 잔여 버퍼 플러시
  - 토픽명·플러시 주기 등 전부 환경변수 — 토픽 통일 결정 시 compose 한 줄만 변경
- **검증 결과: 리플레이 1,000건 발행 → 적재 1,000행 (유실 0), Parquet 읽기 재검증 1,000행 일치**
  - 파티션 구조 `house=H001~H010/date=2026-09-03/` 확인

### 3. 트러블슈팅 (팀 공유 필요 ⚠️)

- **infrastructure `.env` 누락**: 메인 compose는 `infrastructure/.env` 필요 (gitignore 대상) → `.env.example` 복사로 해결. pull 받은 팀원 전원이 겪을 이슈
- **mosquitto 재시작 루프**: gitignore된 `passwd` 파일이 없으면 도커가 같은 이름의 **폴더**를 만들어버려 브로커가 죽음
  - 해결: 폴더 삭제 → `mosquitto_passwd`로 파일 생성 → **chmod 644 필수** (600이면 mosquitto 유저가 못 읽어 또 죽음) → 컨테이너 재생성
- **Kafka 토픽 자동 생성 꺼짐**: `power-raw` 수동 생성 필요 (파티션 8) — 생성 스크립트화 예정

## 배운 점

- 도커가 존재하지 않는 파일을 바인드 마운트하면 폴더를 만들어버린다 → gitignore된 설정 파일은 README에 생성 절차가 반드시 필요
- Windows 호스트에서 HDFS 쓰기는 Hadoop 클라이언트 의존성이 커서, 적재기를 컨테이너로 만들어 도커 네트워크 안에서 WebHDFS로 쓰는 쪽이 훨씬 깔끔함
- at-least-once 보장은 "커밋 시점을 플러시 성공 뒤로 미루는 것"만으로 구현 가능 — 중복은 배치 레이어에서 제거 가능하지만 유실은 복구 불가이므로 원본 적재 레이어에 맞는 선택
