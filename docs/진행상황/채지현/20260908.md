# 진행 상황 회고 (0908, 채지현)

## 오늘 한 일 — MVP 2안 정의 (분산 포함형)

### 증명할 것 두 가지

1. 총 전력만 보고 가전 ON/OFF를 맞히고, 루틴 이탈을 표시한다 (**기능 증명**)
2. 그 처리가 분산 파이프라인 위에서, 다가구 규모 트래픽으로 돈다 (**아키텍처 증명**)

핵심 설계 판단: 기능은 **실측 1가구**로, 분산은 **리플레이 가상 다가구**로 증명 — 두 증명을 한 데이터로 하려 하면 둘 다 어려워짐.

### 만드는 것 (In)

| # | 구성 요소 | 스펙 |
| --- | --- | --- |
| 1 | 센서 노드 1대 + 가전 3종 | 1안과 동일 (포트·전자레인지·선풍기) |
| 2 | Kafka | 브로커 1대, `power-raw`(파티션 8, 가구 키) / `detected-events` |
| 3 | 리플레이 프로듀서 | AI-Hub 샘플 10가구 타임스탬프 순 재생 — 실측 1 + 가상 10 = 11가구 트래픽 |
| 4 | Spark Structured Streaming | 가구별 슬라이딩 윈도우 이동평균 감지 + Redis 시그니처 매칭 (규칙 기반) |
| 5 | HDFS (또는 MinIO) | `power-raw` → Parquet 적재 (`house=/date=` 파티션, 1분 트리거) |
| 6 | Spark 배치 잡 1개 | 일 1회: 이벤트 누적 → 가구별 루틴 통계(평균±표준편차) → MySQL 갱신. **람다 구조 성립의 최소 단위** |
| 7 | Redis + MySQL | 시그니처 사전·현재 상태 / 루틴 프로파일·알림 이력 |
| 8 | 화면 1장 + 알림 1개 | 실측 가구 실시간 카드 + 11가구 모니터링 그리드 + 루틴 이탈 문자 |

### 안 만드는 것 (Out)

- ❌ 딥러닝 (Seq2Point/UNet) — 규칙 기반만, AI 베이스라인 비교는 MVP 이후
- ❌ AI-Hub 110가구 전체 — 리플레이 10가구면 분산 증명에 충분
- ❌ Airflow — 배치는 cron 한 줄로 시작
- ❌ 본인 확인 에스컬레이션, 여행 모드, 자가 캘리브레이션
- ❌ 워커 8대 성능 실험 — MVP는 "돈다"까지, 스케일 곡선(RQ0)은 다음

### 구조

```
[실측] ESP32 ──MQTT──┐
                      ├─> Kafka(power-raw) ─┬─> Spark Streaming ──> Redis ──> 대시보드
[가상] 리플레이 ×10 ──┘                     │      (감지+매칭)              └> 알림
                                            └─> HDFS 적재(Parquet)
                                                     │
                                            Spark 배치(일 1회, cron)
                                                     │
                                              루틴 통계 → MySQL
```

전부 노트북 1대의 docker-compose: Kafka 1 + Spark 마스터 1·워커 2 + HDFS(NameNode 1·DataNode 1) + Redis + MySQL.

### 완성 판정 기준 (DoD)

1. 실측: 포트 ON → 5초 내 화면 표시, 30회 테스트 정확도 80%+ (1안과 동일)
2. **분산: 11가구 트래픽(초당 ~110 메시지)이 유실 없이 흐르고, Spark UI에서 워커 2대 동작 확인**
3. **적재: HDFS에 가구/날짜 파티션 Parquet이 쌓이고, 배치 잡이 읽어 루틴 통계 갱신**
4. 알림: 실측 가구의 "아침 포트 미사용" 문자 실제 발송

DoD 2·3이 1안 대비 추가된 아키텍처 증명. 리플레이 10배속에도 버티면 시연 임팩트 상승.

### 일정 (3주 = 1안 2주 + 1주)

- 1주차: 인프라 — compose 스택 기동(2일), 리플레이 프로듀서(1일), Kafka→HDFS 적재 잡(2일) / 병행: 센서 조립
- 2주차: 감지 로직 파이썬 검증(2일) → Spark Streaming 이식(2일), 시그니처 3장 + Redis(1일)
- 3주차: 배치 루틴 잡(2일), 대시보드+알림(2일), 통합 테스트+DoD 측정(1일)

### 리스크 & 폴백

| 리스크 | 폴백 |
| --- | --- |
| Spark Streaming 이식 난항 | 감지는 파이썬 Kafka 컨슈머, Spark는 배치만 — 람다 구조는 성립 |
| HDFS 구축 난항 | MinIO 컨테이너 1개로 교체 — 경로 한 줄 수정 |
| 노트북 리소스 부족 | 워커 2→1, 리플레이 10→5가구 축소 — 구조 증명 지장 없음 |

### 한 줄 요약

기능 MVP에 "Kafka 리플레이 + Spark(스트리밍·배치) + HDFS 적재"를 얹되, **실측(1가구)으로 기능을, 리플레이(10가구)로 분산을 증명**하는 이원 구조. "돈다"와 "빠르다/크다"를 구분해 MVP는 "돈다"까지만 책임진다.
