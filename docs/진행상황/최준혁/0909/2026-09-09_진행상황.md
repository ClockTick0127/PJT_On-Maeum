## 2. 상세 진행 내용

### (1) routine_missed 이상 감지 시나리오 설계

NILM AI 모델의 "루틴 누락" 이상 감지 능력을 테스트하기 위한 시나리오로, 정해진 시각에 발생해야 하는 가전 가동 패턴이 나타나지 않을 때 이를 감지하는 기능을 시뮬레이션합니다.

```text
[ routine_missed 시나리오 타임라인 ]

정상 패턴 (매일 08:10 KST):
  08:10:00  전기포트 가동 시작 (1,700W)
  08:13:00  전기포트 자동 정지
  → AI 모델: 정상 루틴으로 판정

이상 패턴 (루틴 누락):
  08:10:00  전기포트 가동 없음
  ...300초 경과...
  08:15:00  300초 윈도우 초과 → 루틴 누락 경보 발령
  → AI 모델: routine_missed 이상 판정
```

* **트리거 조건**: 08:10 KST 기준, 300초(5분) 윈도우 내에 전기포트(1,700W 이상) 가동 이벤트가 감지되지 않으면 이상으로 판정
* **웹 대시보드 연동**: 브라우저에서 시나리오 선택 후 원클릭 실행, 실시간 이벤트 로그에 감지 상태 표시

### (2) MQTT TLS 인증서 E2E 검증 아키텍처

프로덕션 환경의 TLS 보안 체인을 로컬에서 완전히 재현하여 배포 전 사전 검증을 수행했습니다.

```text
[로컬 E2E 테스트 구성]

+----------------------------+     TLS 8883      +----------------------------+
|  Python paho-mqtt Client   | ═══════════════> |  Mosquitto (Docker)         |
|  - tls_set(ca_certs=ca.crt)|     (SAN: IP)     |  - server.crt + server.key |
|  - username/password Auth  |                   |  - passwd (mosquitto_passwd)|
+----------------------------+                   +----------------------------+
         │                                                    │
         │  1. TLS Handshake                                  │
         │     ca.crt로 server.crt 검증                        │
         │  2. SAN IP 매칭 (CERT_REQUIRED)                    │
         │  3. Username/Password 인증                         │
         │  4. MQTT Pub/Sub 메시지 교환 ✓                     │
         └────────────────────────────────────────────────────┘
```

**검증 항목 및 결과**:

| 검증 항목            | 방법                                      | 결과                          |
| :------------------- | :---------------------------------------- | :---------------------------- |
| CA 인증서 발급       | `openssl req -x509 -newkey rsa:2048`      | ✅ CN=nilm-mqtt-ca             |
| 서버 인증서 SAN      | `openssl x509 -noout -ext subjectAltName` | ✅ IP 매칭 확인                |
| TLS 핸드셰이크       | `openssl s_client -connect`               | ✅ Verify return code: 0 (ok)  |
| 계정 인증            | `mosquitto_passwd -c` → paho-mqtt 접속    | ✅ CONNACK 수신                |
| Pub/Sub 메시지 교환  | paho-mqtt client 양방향 통신              | ✅ 메시지 정상 수신            |
| 잘못된 인증서 거부   | 임의 ca.crt로 접속 시도                   | ✅ SSL_ERROR 발생 (정상 거부)  |
| 잘못된 비밀번호 거부 | 틀린 password로 접속 시도                 | ✅ CONNACK refused (정상 거부) |

## 3. 트러블슈팅

### (1) Windows WSL 환경에서 Docker 기반 MQTT TLS 테스트 불가

* **증상**: 로컬 Windows 환경에서 Docker 컨테이너 기반 Mosquitto TLS 테스트 시 `sudo` 명령이 비활성화되어 있어 컨테이너 내부 파일 권한 설정(uid 1883) 및 `mosquitto_passwd` 실행 불가
* **원인**: Windows 11의 개발자 설정(Developer Settings)에서 `sudo` 기능이 비활성화된 상태. WSL이 아닌 네이티브 Windows PowerShell에서는 `sudo`가 기본적으로 사용 불가
* **해결**: Docker Desktop의 `docker exec` 명령으로 컨테이너 내부에 직접 접근하여 `mosquitto_passwd` 실행. 파일 권한은 Docker Volume 마운트 시 호스트 측에서 사전 설정하는 방식으로 우회

### (2) paho-mqtt TLS 접속 시 `ssl.SSLCertVerificationError` 발생

* **증상**: Python paho-mqtt 클라이언트에서 `tls_set(ca_certs="ca.crt")`로 TLS 접속 시도 시 `[SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: IP address mismatch` 에러 발생
* **원인**: 서버 인증서 발급 시 SAN(Subject Alternative Name)에 IP를 등록하지 않고 CN(Common Name)만 설정한 경우, OpenSSL 1.1+ / Python 3.10+에서는 CN 매칭을 무시하고 SAN만으로 호스트를 검증함
* **해결**: 서버 인증서 발급 시 `san.cnf` 확장 파일에 `subjectAltName=IP:<접속IP>`를 명시하여 SAN에 접속 IP를 정확히 등록. `openssl x509 -noout -ext subjectAltName`으로 SAN 등록 여부를 사전 확인 후 접속 테스트 수행

### (3) Mosquitto 컨테이너 기동 시 `Error: Unable to open password file` 오류

* **증상**: Docker Compose로 Mosquitto 기동 시 `Error: Unable to open password file "/mosquitto/config/passwd"` 에러와 함께 컨테이너가 즉시 종료
* **원인**: `mosquitto_passwd` 도구로 생성한 계정 파일의 소유자가 호스트의 현재 사용자로 설정되어 있고, Mosquitto 컨테이너 내부 프로세스(uid 1883)에 읽기 권한이 없음
* **해결**: 호스트에서 `passwd` 파일 생성 후 `chown 1883:1883`, `chmod 640`으로 권한을 Mosquitto 프로세스 uid에 맞춤. Docker Volume 마운트 경로와 `mosquitto.conf`의 `password_file` 경로 일치 여부도 함께 확인

### (4) 로컬 개발환경(1883)과 프로덕션 TLS(8883) 설정 혼동

* **증상**: 로컬 `compose.yaml`의 Mosquitto가 1883(비인증)으로 동작 중인 상태에서 TLS 8883 설정을 적용하자 기존 시뮬레이터(`web_server.py`)의 MQTT 발행이 중단됨
* **원인**: `mosquitto.conf`에 TLS 리스너만 남기고 기존 1883 리스너를 삭제하여 로컬 개발 파이프라인이 끊긴 것
* **해결**: 프로덕션 설정(`mosquitto.production.conf`)과 로컬 개발 설정(`mosquitto.conf`)을 분리 관리하는 기존 구조를 유지. TLS 테스트는 별도 Docker Compose 파일(`docker-compose.tls-test.yaml`)로 격리 실행하여 기존 로컬 환경에 영향을 주지 않도록 조치
