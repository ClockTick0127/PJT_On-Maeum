### (2) NILM 4대 물리 전력 특성 수식 및 모델링 로직 (`simulator.py`)

기존의 단순 유효전력 난수 생성 방식은 AI 모델이 가전의 전기적 특성을 분해하기에 정보량이 부족했습니다. 이에 따라 교류(AC) 회로 이론 및 AI Hub 실측 데이터셋(71685)을 결합한 다변량 전력 계산 엔진을 구현했습니다.

* **물리 전력 연산 수식**:
  1. 가전별 유효전력($P$) 및 무효전력($Q$) 산출:
     $$Q = P \times \tan(\arccos(PF))$$
  2. 기동 돌입전류(Inrush Current) 감쇠 모델링:
     $$P_{inrush}(t) = P_{base} \times (Multiplier - 1.0) \times \left(1.0 - \frac{t}{T_{inrush}}\right)$$
  3. 분전반 메인 계측기 전체 전력 합성:
     $$P_{total} = P_{base\_load} + \sum P_{appliance} + \mathcal{N}(0, 0.8)$$
     $$Q_{total} = Q_{base\_load} + \sum Q_{appliance} + \mathcal{N}(0, 0.8)$$
  4. 피상전력 (Apparent Power, S):
     $$S = \sqrt{P_{total}^2 + Q_{total}^2} \quad (\text{단위: VA})$$
  5. 종합 역률 (Power Factor, PF):
     $$PF = \frac{P_{total}}{S} \quad (0.00 \le PF \le 1.00)$$
  6. 종합 전류 (Current, I):
     $$I = \frac{S}{V} \quad (\text{단위: A, } V \approx 220\text{V})$$

* **발행 메시지 JSON 스키마**:
  ```json
  {
    "house": "H001",
    "device": "main",
    "ts": "2026-09-07T08:30:00.123Z",
    "power_w": 2845.50,
    "active_power": 2845.50,
    "reactive_power": 812.30,
    "apparent_power": 2959.20,
    "power_factor": 0.962,
    "voltage": 220.3,
    "current": 13.433
  }
  ```
  - `power_w`: 기존 Kafka Bridge, HDFS Loader 등 다운스트림과의 호환성을 유지하기 위한 기본 유효전력 필드
  - `active_power`, `reactive_power`, `power_factor`, `current`: NILM AI 모델의 핵심 다변량 입력 피처 4종

### (4) 시뮬레이터 CLI 실행 유연성 및 동적 확장 설계

시뮬레이터를 소규모 개발 검증부터 대규모 부하 스트레스 테스트까지 자유롭게 활용할 수 있도록 `argparse` 기반의 CLI 인자를 구현했습니다.

* **CLI 주요 옵션**:
  - `--houses`, `-n`: 대상 가구 수 (기본값: 10, 임의의 N가구 지원)
  - `--interval`, `-i`: 발행 주기 초 단위 (기본값: 1.0초)
  - `--hz`: 초당 발행 횟수 (예: `--hz 2` 입력 시 0.5초 주기로 자동 계산)
  - `--count`, `-c`: 발행 사이클 횟수 (기본값: 0, 0일 경우 무한 발행)
  - `--host`, `-p`: 브로커 주소 및 포트 (기본값: localhost:1883)
  - `--user`, `--password`: MQTT 인증 계정 (기본값: simulator_user / test1234)
  - `--qos`: MQTT 발행 QoS 레벨 (0 또는 1, 기본값: 1)
  - `--quiet`, `-q`: 요약 모드 (초 단위 개별 로그를 생략하고 5초 단위로 누적 건수 및 실시간 TPS 출력)

* **동적 가구 상태 관리 구조**:
  기존의 고정 가구 딕셔너리 구조를 개선하여, `init_simulation_states(houses)` 함수가 호출될 때 입력받은 가구 수에 맞춰 각 가구별 가전 상태 머신(현재 듀티 사이클, 잔여 가동 시간, 위상 오프셋)을 동적으로 생성하도록 리팩토링했습니다.

* **aiomqtt 비동기 큐 병목 해결**:
  `aiomqtt` 라이브러리는 기본적으로 처리 대기 중인 비동기 호출(`pending_calls`)이 10건을 초과하면 경고 로그를 출력합니다. 수백 가구가 `asyncio.gather`로 1초에 동시 발행될 때 발생하는 경고 스팸을 방지하기 위해 가구 수에 비례하여 임계값을 자동 계산하도록 개선했습니다:
  ```python
  client.pending_calls_threshold = max(len(houses) * 4, 200)
  ```

1. **aiomqtt 비동기 큐 임계치 병목 현상**:
   - 증상: 100가구 이상 동시 발행 시 `aiomqtt.exceptions.MqttCodeError` 및 `pending_calls_threshold (10)` 초과 경고가 터미널에 수천 줄씩 출력됨
   - 원인: aiomqtt의 기본 내부 큐 제한치가 10건으로 고정되어 있어, 수백 가구가 동시에 비동기 코루틴으로 발행을 요청할 때 병목 발생
   - 해결: 브로커 연결 직후 가구 수에 맞춰 `client.pending_calls_threshold = max(len(houses) * 4, 200)`으로 동적 확장하여 경고 없이 매끄러운 전송 달성
2. **브릿지-로더 간 Kafka 토픽명 불일치 파악**:
   - 증상: 브릿지는 정상 구동되어 Kafka로 데이터를 보내지만, HDFS 로더에 데이터가 적재되지 않음
   - 원인: 브릿지는 `power.raw.v1` 토픽으로 발행하고 있었으나, HDFS 로더 컨테이너는 기본값으로 `power-raw`를 구독하고 있어 파이프라인이 단절됨
   - 조치: 환경변수를 통해 토픽을 수동 동기화할 수 있음을 확인하였으며, 팀 차원에서 토픽명을 `power.raw.v1` 규격으로 최종 통일하기로 협의 진행
