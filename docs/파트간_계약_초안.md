> 작성: 채지현 (0914). 아래는 **제안**이며 파트 3(실시간 분석)·파트 4(모니터링)·인프라 합의로 확정한다.
> 확정 시 이 문서가 계약의 원본이 되고, 변경은 MR로만 한다.

## 1. Kafka 토픽 명명 규칙 (결정 필요 ①)

**현황 문제**: 브릿지는 `power.raw.v1`, 리플레이 시뮬레이터·HDFS 적재기는 `power-raw`로 발행/구독 — 불일치.

**제안**: `<도메인>.<데이터>.<버전>` 규칙으로 통일. 버전 접미사는 스키마 변경 시 신구 토픽 병행 운영을 가능하게 한다.

| 토픽 | 내용 | 생산자 | 소비자 | 파티션 |
| --- | --- | --- | --- | --- |
| `power.raw.v1` | 가구별 합산 전력 측정치 | 브릿지, 리플레이 | 실시간 분석, HDFS 적재기 | 8 (key=house_id) |
| `power.events.v1` | 감지된 가전 온오프 이벤트 | 실시간 분석 | 모니터링 | 8 (key=house_id) |
| `power.alerts.v1` | 루틴 이탈 등 알림 이벤트 (2차) | 모니터링 | 알림 발송기 | 4 |

- Kafka `auto.create.topics=false`이므로 **토픽 생성 스크립트**를 `infrastructure/kafka/create-topics.sh`로 추가 (담당: 채지현, 통일 확정 후)
- 확정 시 수정 대상: 리플레이 producer.py, HDFS loader, consumer_check.py (전부 env로 빼둠 — 한 줄 수정)


## 3. 감지 이벤트 스키마 (결정 필요 ② — 파트 3↔4 핵심 계약)

**제안** (`power.events.v1`):

```json
{
  "event_key": "H001:kettle:2026-09-14T07:03:12Z:ON",  // 멱등 키 — 소비자 중복 제거 기준
  "house": "H001",
  "appliance": "kettle",           // 가전 카테고리 (부록 A 코드표)
  "event_type": "ON",              // ON | OFF
  "event_ts": "2026-09-14T07:03:12.174Z",  // 사건 발생 시각 (파형 기준)
  "confidence": 0.96,              // 0~1
  "detected_ts": "2026-09-14T07:03:14.021Z" // 감지 시각 (지연 측정용)
}
```

- **event_key 규칙**: `{house}:{appliance}:{event_ts 초 단위 절삭}:{event_type}` — 생산자(파트 3)가 생성, 소비자(파트 4)는 unique 제약으로 중복 무시
- at-least-once 전제: **중복은 가능, 유실은 없음** — 중복 제거는 소비자 책임

### 부록 A. 가전 카테고리 코드 (초안)

`kettle, microwave, fan, fridge, washing_machine, tv, rice_cooker, unknown`

## 5. 공유 식별자 규칙 (재확인)

- **house_id**: `H` + 3자리 숫자 (`H001`), varchar(10) — device_db가 원본, 타 서비스는 값 참조(FK 금지). Kafka 파티션 키·HDFS 파티션(`house=H001`)과 동일 값
- **keycloak_user_id**: UUID — Keycloak이 원본, 서비스들은 값 참조. 가구-보호자 매핑은 device_db `household_guardians`가 원본 (조회 API: `GET /api/devices/households/{houseId}/guardians`)

## 6. MQTT 계층 (참고 — 파트 1+2 소관, 정보 공유)

- 토픽: `v1/power/sim/{house_id}/main`, 기기 계정은 자기 가구 패턴만 PUBLISH (ACL)
- 기기 계정 발급·로테이션·폐기는 iot-device-service API → passwd/ACL 파일 동기화(`/api/devices/admin/mqtt/sync`)
- ⚠️ 브로커 conf에 `acl_file` 활성화 시 **파일에 없는 계정(simulator_user, 브릿지)은 전 토픽 차단**되므로, 활성화 전 공용 계정 항목 관리 방안 합의 필요
