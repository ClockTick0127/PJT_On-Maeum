# 0909 MQTT 인증서 발급 실행 기록

## 0. A: 디렉터리 준비

`prepare.sh`가 `jenkins-agent`로 `/opt/nilm/mqtt/mosquitto.conf`를 쓰므로 `mqtt/`는 Agent 소유여야 합니다.

```bash
sudo install -d -m 755 -o jenkins-agent -g jenkins-agent /opt/nilm/mqtt && sudo install -d -m 755 /opt/nilm/mqtt/certs
```

## 1. A: 자체 CA + 서버 인증서 생성

작업 폴더는 홈에 두고, `ca.key`는 나중에 기기 인증서나 재발급에 필요하니 보관합니다.

```bash
mkdir -p ~/mqtt-ca && chmod 700 ~/mqtt-ca && cd ~/mqtt-ca
```

CA 생성 (10년):

```bash
openssl req -x509 -newkey rsa:2048 -nodes -days 3650 -keyout ca.key -out ca.crt -subj "/CN=nilm-mqtt-ca"
```

서버 키·CSR 생성:

```bash
openssl req -newkey rsa:2048 -nodes -keyout server.key -out server.csr -subj "/CN=nilm-mqtt"
```

CA로 서명 — SAN에 B가 접속할 주소를 넣습니다. IP로 접속하므로 `IP:` 타입입니다.

```bash
openssl x509 -req -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial -days 3650 -out server.crt -extfile <(printf "subjectAltName=IP:<PRIVATE_IP>\nextendedKeyUsage=serverAuth")
```

SAN 확인:

```bash
openssl x509 -in server.crt -noout -ext subjectAltName
```

`IP Address:<PRIVATE_IP>`가 나와야 합니다. 나중에 도메인으로 붙일 계획이면 `IP:172.26.8.92,DNS:mqtt.example.com`처럼 콤마로 추가하면 됩니다.

## 2. A: 인증서 배치

mosquitto 컨테이너는 uid 1883으로 동작하므로 개인키는 1883만 읽게 합니다.

```bash
sudo install -m 644 ~/mqtt-ca/server.crt /opt/nilm/mqtt/certs/server.crt && sudo install -m 640 -o 1883 -g 1883 ~/mqtt-ca/server.key /opt/nilm/mqtt/certs/server.key
```

## 3. A: 계정 파일 생성

`mosquitto_passwd`를 따로 설치하지 않고 이미지 안의 것을 씁니다. 비밀번호는 프롬프트로 입력(명령줄에 안 남음).

```bash
sudo docker run --rm -it -v /opt/nilm/mqtt:/work eclipse-mosquitto:2 mosquitto_passwd -c /work/passwd kafka_bridge_user
```

```bash
sudo chown 1883:1883 /opt/nilm/mqtt/passwd && sudo chmod 640 /opt/nilm/mqtt/passwd
```

여기서 정한 사용자명·비밀번호가 B `.env`의 `MQTT_USER`/`MQTT_PASS`가 됩니다.

## 4. A 최종 확인

```bash
sudo ls -laR /opt/nilm/mqtt
```

```text
mqtt/            jenkins-agent 755
mqtt/passwd      1883:1883     640
mqtt/certs/      root          755
mqtt/certs/server.crt  root    644
mqtt/certs/server.key  1883    640
```

`jenkins-agent`는 `test -s`로 존재만 확인하므로 개인키 읽기 권한이 없어도 통과합니다.

## 5. B: `ca.crt` 복사

`ca.crt`는 공개 인증서라 내용을 그대로 옮겨도 됩니다. A에서 출력:

```bash
cat ~/mqtt-ca/ca.crt
```

B에서 붙여넣기(전체 `-----BEGIN…END-----` 포함):

```bash
sudo install -d -m 755 -o jenkins-agent -g jenkins-agent /opt/nilm/mqtt && sudo install -d -m 755 /opt/nilm/mqtt/certs && sudo tee /opt/nilm/mqtt/certs/ca.crt > /dev/null
```

붙여넣은 뒤 `Ctrl+D`. 확인:

```bash
sudo chmod 644 /opt/nilm/mqtt/certs/ca.crt && openssl x509 -in /opt/nilm/mqtt/certs/ca.crt -noout -subject
```

`CN = nilm-mqtt-ca`가 나오면 됩니다. B의 `/opt/nilm` 소유자가 `jenkins-agent`가 아니면 A와 같게 맞춰주세요.

## 6. B `.env` 수정 → Jenkins `ec2-b-runtime-env` 재업로드

```dotenv
MQTT_HOST=<PRIVATE_IP>
MQTT_PORT=8883
MQTT_USER=kafka_bridge_user
MQTT_PASS=<3단계에서 입력한 비밀번호>
MQTT_CA_FILE=/etc/mqtt/ca.crt
```

`MQTT_HOST`는 1단계 SAN과 정확히 같은 문자열이어야 합니다. Bridge는 `CERT_REQUIRED`로 호스트 검증을 하므로 다르면 연결이 거부됩니다.

## 7. 보안 그룹

EC2-A 인바운드 8883을 EC2-B의 사설 IP(또는 B 보안 그룹)에서만 허용. ESP32 기기가 외부에서 붙기 시작하면 그때 넓힙니다.

## 마무리

* `~/mqtt-ca/ca.key`는 그대로 두되 `chmod 600`. 잃으면 기기 인증서를 이 CA로 발급할 수 없습니다.
* `~/mqtt-ca/server.key`는 배치가 끝났으니 지워도 됩니다: `shred -u ~/mqtt-ca/server.key ~/mqtt-ca/server.csr`
* 인증서 유효기간 10년이라 갱신 걱정은 없지만, 팀 문서에 CA 위치를 적어두세요.

여기까지 되면 `prepare.sh`가 검사하는 A·B 파일이 모두 준비되고, 이전에 말한 5개 파일 주석 처리는 필요 없습니다.
